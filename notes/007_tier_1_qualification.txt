Runtime composition:
  conix.resilience.supervisor.supervise(catalog, database_dsn, stop)
    -> conix.resilience.rpc_retry.run_with_read_retries(...)
      -> ORIGINAL conix.app.run(...)
        -> original core.open_writer / source identity and journal lock
          -> original Writer.advance_one / RPC.call / Journal.publish_block.
No new normal block loop, transport, journal, scanner, reader, source-specific
algorithm, database progress registry, repair or external process orchestrator.
The supervisor controls only when to RESTART this complete application call.

Policy: only a caught RpcUnavailable with a ConnectError, ConnectTimeout,
ReadError or ReadTimeout as its explicit cause is restartable. These are
shared with T1-A's read classification; a TimeoutError from a single read
can be retried inside its ORIGINAL T1-A deadline but may NOT restart the
whole application when that deadline might be exhausted. Provider
rejections, missing evidence, source/schema/branch conflicts, SQL
unavailability, uncertain COMMIT and unconfirmed retirement remain errors.
Two bounded restarts with 100 ms and 200 ms cancellable waits are allowed.
The original error is re-raised on exhaustion or a concurrent stop.
Cancellation propagates and cannot admit a subsequent session.

Contained witness: injected THREE selected-log transport failures into
the original RPC.call at one real Anvil block. T1-A exhausted its attempt
budget; the previous original app.run/open_writer retired its SQL
connection before T1-B invoked the same application in a fresh session.
Observed original Journal.publish_block and retained source ID, block
progress and history generation through independent SELECT-only SQL.
Negative tests include provider HTTP rejections, unknown COMMIT, blocked
history, request/deadline timeout, cancellation during active work and
backoff, and failed retirement. All tests use existing disposable sources.

Limits: this is an opt-in in-process APPLICATION SESSION supervisor,
not a deployed supervisor, child-process manager, generalized SQL retry
policy, automatic reorganization repair, or durable multi-process leader
election. GitHub-hosted CI is NOT the selected rootless Engine. T1-B
requires a revision-bound test/indexer/run on fw/rootless agentic, plus
independent review, before integration. Tier 1-C/D still own checked
reorganization automation and broader unattended recovery, including
PostgreSQL restarts and unknown COMMIT reconciliation. Nothing is merged
from the old main-tier-1 branch, whose follow() loop duplicated Tier 0.
