Conix — named deployment Make contract (Tier-0-7 B)
================================================
12 November 2026

Normal operator interface
-------------------------
Each saved deployment has exactly one identity and one retained nonsecret
selection under ignored config/deployments/<name>/deployment.toml. Creation
is exclusive; no command overwrites an existing deployment definition.
No default deployment or implicit Docker context is allowed.

Make targets use <resource>[/<subject>]/<action>. Public application lifecycle:

  deployment/init              Save one named definition (first-time interactive
                               prompts for missing nonsecret paths/selectors).
  deployment/prepare           Offline image build/admission and private input
                               snapshot, with an exact prepared receipt.
  deployment/database/init     Owner-authorized one-shot schema initialization
                               against separately provisioned SQL roles/schema.
  deployment/config/check      Check a prepared Compose graph without mutation.
  deployment/up                Admit and start only the prepared service.
  deployment/status            Inspect selected project's owned containers.
  deployment/logs              Display a bounded tail from one owned container.
  deployment/down              Retire selected owned indexer containers only.

  test/standalone/run          Build cached runner and execute the actual
                               installed CLI in an owned disposable Anvil/PG
                               stack; retire it and preserve failure causes.

After initialization, only DEPLOYMENT=<name> is needed for ordinary repeated
operations. The saved Docker context is the sole authority; a conflicting
explicit override fails. Missing declarations may be recovered only for
status/logs/down with an explicit DOCKER_CONTEXT. The saved declaration
may not be used to supply credentials via argv or environment.

First-time init:
  make deployment/init DEPLOYMENT=local DOCKER_CONTEXT=agentic

The init command requires the following selections, prompting from /dev/tty
only when interactive and absent: CONFIG_FILE, DSN_FILE, OWNER_DSN_FILE,
DATABASE_NETWORK, RPC_NETWORK, WHEELHOUSE. All host paths are absolute.
The source config and adjacent declared ABIs are immutable after staging.
The runtime and owner DSN are separate operator-owned mode-0600 files.
The owner DSN is never staged in the indexer volume.

Ordered operational commands:
  make deployment/prepare DEPLOYMENT=local
  make deployment/database/init DEPLOYMENT=local
  make deployment/config/check DEPLOYMENT=local
  make deployment/up DEPLOYMENT=local
  make deployment/status DEPLOYMENT=local
  make deployment/logs DEPLOYMENT=local
  make deployment/down DEPLOYMENT=local

Preparation uses the checked wheelhouse and pinned base images on the
selected local Engine; offline CI can prepare on a rootful Engine, but actual
deployment/up and database/init require a verified rootless Engine. Missing
artifacts require explicit separate acquisition. Successful image/staging admission produces an owner-only
prepared receipt naming the exact immutable image ID and private volume ID.
Failed preparation does not publish a candidate. Repreparing refuses a live
service; old input state is retired only after a replacement was prepared.
No second generic Docker orchestration framework is installed.

Schema initialization assumes precreated database/schema roles from the
existing owner-only contract. Only the selected conix_owner role may create
tables and grant runtime/read privileges. A short-lived confined networked
initializer reads the owner credential via private stdin and calls the
installed conix.schema.initialize(). The normal service never gets the
owner credential or DDL authority. No migration, implicit DB provisioning
or automatic replay of an uncertain initialization.

Up may use only the prepared image/input and two separately admitted existing
internal bridges. The maintained operator creates the container stopped,
checks the actual image, UID, mounts, capabilities, networks and resource
limits, then starts it. Status/logs/down work without the prepared receipt
and do not delete external SQL, networks, private volume or images.
No implicit acquisition, rebuild, schema installation, retry or reorg repair.

Legacy low-level operations remain for explicit diagnostics/maintenance:
history/advance, deployment/inputs/create, deployment/inputs/remove,
test/postgres/run, the separate image and wheelhouse targets, and
campaign/indexer/acceptance/run. They are not alternate normal deployment
flows. deployment/start and deployment/remove are NOT exported aliases.

Trust and tests
---------------
The operator alone constructs Docker subprocess argument arrays; Make captures
literal command-line values without evaluating them. Credentials never enter
container argv, image layers, labels or ordinary logs. Owner and runtime
identities stay separate. The existing checked scanner/publisher/reader and
explicit repair remain the single source of truth. Avoid duplicate validators
or generic lifecycle registries.

Test the real Make surface, saved configuration and privilege selection,
failure boundaries, Docker admission and cleanup, installed process and
its SIGTERM behavior, durable SQL checkpoints, tip release and later arrival.
The disposable suite and repository checks do not establish retained-service
production readiness or all dapp32 consumer behavior.
