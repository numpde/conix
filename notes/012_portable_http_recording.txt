Portable HTTP recording with WARC
=================================

Date: 2026-11-15
Status: implementation brief; capture and replay are not implemented.

Purpose and authority
----------------------
Record real provider interactions once, without decoding EVM data, rewriting
JSON or replacing provider errors in the archive. Produce an ordinary WARC
that other projects can inspect and reuse without Conix. Recording is useful
before replay exists. Portable capture is the first deliverable; realistic
stress replay is a later consumer, not a prerequisite.

This note owns the recording artifact and the order of this work. Note 005
continues to own physical history acquisition and Tier-2 substitution;
Note 004 owns indexing correctness; Note 002 owns Make/Docker authority.
Note 011 owns measured rates and existing synthetic workload evidence.
A recording neither supersedes those observations nor proves canonicality,
complete event history, provider honesty or sustainable indexing throughput.

Keep the premise: the original minimal Tier-0 application remains fully in
use. Recording belongs to test/acquisition tooling, not the installed scanner,
journal, Reader or Tier-1 recovery policy. Keep implementation on the current
Tier-0-based research branch; promotion to maintained branches is separate.
No production activation, chain transaction or sibling source edit is needed.

The prioritization gradient
-----------------------------
0. Inevitable: implement A below. Deliver a portable WARC from genuine HTTP.
   Use the existing HTTPX client and warcio; no second HTTP stack, monkey
   patch, proprietary archive format or general proxy framework. Capture is
   useful without replay. Do not make A depend on B or C.

1. Necessary for public capture: implement B. Pair exchanges, preserve raw
   content, mark missing/truncated responses, enforce finite resource grants
   and retain incomplete evidence. A successful process exit alone does not
   establish a complete recording. Test the concrete ways these claims fail.

2. Valuable next: implement C. Reuse the archive for exact serial replay with
   no upstream fallback and one original Conix/PostgreSQL/Reader witness.
   This qualifies a recorded scenario, not live throughput.

3. Conditional: normalize JSON-RPC IDs only after an actual replay needs it;
   preserve the archive. Add concurrency, finer timing, indexes or rotation
   only for a real consumer/scale limit. Admit overlap only with corresponding
   pairing/order proof. Derived artifacts remain rebuildable from WARC.
   Keep-pace stress requires a head advancing with elapsed time, independently
   of polling. A tape that advances once per poll conceals a slow client's
   backlog. Defer that feature; missing block/log evidence is unavailable,
   not an invented empty result.

4. Low priority: broader chain/provider coverage, performance campaigns,
   additional exports and crash salvage. Each needs a question the existing
   artifact cannot answer; none blocks the first useful capture.

5. Validation fetish: no arbitrary test counts, duplicated proofs, missing-
   module RED theater, repeated unchanged CI, all-network campaign before one
   archive, endless reviewer rounds, broad hostile-client certification or
   second format kept in sync. A hash proves identity, not fidelity; two
   tools accepting a file is weaker than checking actual bytes and linkage.
   One relevant counterexample beats a large ceremony that can pass for the
   wrong reason. Run checks for the changed effect boundary, not every past
   release gate. Preserve revision-bound evidence and state omissions.

Artifact and fidelity contract
--------------------------------
The completed public artifact is:

  out/rpc-recordings/<capture-id>/
    capture.warc.gz
    manifest.json

The WARC owns exchange evidence. The manifest owns selected configuration,
recorder/image identity, final archive hash and completed/partial/failed
outcome. Do not duplicate the exchange log in the manifest. Missing manifest
means unconfirmed completion. A hard kill may leave a damaged final record;
retain earlier evidence without automatic salvage or a completeness claim.
Conix ABI/catalog/Reader expectations are separate scenario inputs.

Preserve encoded body bytes and HTTP metadata exposed by the transport,
including duplicate headers and provider error prose. No JSON normalization,
ID rewriting, EVM decoding or archive redaction. HTTPX has already parsed HTTP;
header whitespace, chunk boundaries, HTTP/2 frames and TLS/TCP packets are
outside the fidelity claim. Archive envelopes must describe stored bytes
accurately; retain original observed headers in metadata when adjusted.
A request without an HTTP response has failure metadata, never invented
provider status/content. Partial bodies use WARC-Truncated with their reason.

Output stays private and raw content never enters ordinary terminal output.
Sharing/publishing is separate; sanitized derivatives must be distinguishable.
Use the selected rootless Engine, explicitly reviewed keyless HTTPS source,
read-method admission, verified TLS and existing finite network budgets.
No redirects/retries, ambient proxy selection, published ports, writable
repository bind or consumer egress. Export only after capture retirement.
Keep original failure and independent cleanup outcomes visible. An archive
write failure must not permit an unrecorded success. No unbounded queues.

Implementation work order
---------------------------
The next task is A below. Implement it; do not commission another design
study, select another archive format or wait for the later tasks. Names and
interfaces below are decisions for this implementation, not existing features.

A. Next commit: bounded HTTPX-to-WARC capture and its focused contained test

   Add tools/fixtures/http_recording.py. It imports HTTPX and warcio, never
   Conix, an ABI, a chain fixture or an operator lifecycle. Its public seam:

     RecordingTransport(inner, archive, *, max_request_bytes,
                        max_response_bytes, elapsed_budget_seconds)

   This implements httpx.BaseTransport and delegates actual HTTP/TLS to
   inner, an ordinary httpx.HTTPTransport. The caller owns the archive file;
   transport close retires the inner transport. No monkey-patching, proxy
   server, protocol parser or alternative request serializer is introduced.

   handle_request(request) performs these ordered effects:
   1. Acquire its single in-flight slot without waiting; reject overlap
      before dispatch. Accept an already-buffered request only; use its
      content bytes and raw header pairs without reserializing. Refuse an
      oversized body or an unbuffered streaming request before dispatch;
      streaming request-body support is outside A. Write the WARC request
      record before sending it upstream.
   2. Call inner.handle_request(request). Preserve status, reason, protocol,
      raw header pairs and raw response-stream bytes. Buffer at most the
      supplied response limit. Check elapsed_budget_seconds before dispatch
      and between raw reads. This is not a strict interruptible deadline:
      a blocked read can overshoot by an inner I/O timeout. Keep the inner
      transport's finite timeouts; add no watchdog/cancellation machinery.
   3. Write a linked WARC response, including non-200 and malformed-JSON
      bodies. Use bounded failure metadata when no response arrived, and
      WARC-Truncated for an interrupted or limited body. Close the upstream
      response and release the in-flight slot on every path.
   4. Only after successful recording, return an httpx.Response backed by
      httpx.ByteStream of the captured encoded body. Preserve its original
      headers/extensions for HTTPX's ordinary downstream decoding. Reraise
      original transport failures after recording the partial evidence.
      Recording failure prevents returning an unrecorded success.

   Use warcio.WARCWriter(gzip=True, warc_version='1.1'). Remove transfer
   framing from the archived HTTP envelope and set its length to the stored
   body length; retain the observed original header pairs in linked metadata
   when that envelope differs. Preserve Content-Encoding and encoded payload
   bytes. This also makes truncated archived envelopes internally readable;
   WARC-Truncated and metadata retain the actual observed failure/length.

   The wrapper deliberately buffers before returning response headers to
   its caller. This obtains error bodies that the gateway otherwise would
   not consume. It changes response delivery timing, so it is capture tooling,
   not a transparent latency measurement or a performance-qualified path.
   Keep separate request/header timestamps in WARC; do not claim caller-seen
   latency equals provider latency.

C. Later commit: exact serial replay

   Add a read-only WARC replay transport in the same tooling module and
   tests. Consume complete request/response pairs in recorded serial order;
   compare HTTP method, target, body bytes and Content-Type/Content-Encoding
   header values, preserving duplicate value order. Host is represented by
   the target; transport framing is handled by HTTPX. Ignore only volatile
   headers not used in this matching contract; no JSON-RPC ID normalization.
   Reject mismatch, truncation and exhaustion; report unused pairs at stop.
   It has no inner network transport and never falls back to an upstream.
   Attach it beneath the gateway for one original Conix/PostgreSQL/Reader
   scenario using recorded source evidence. No timing/head progression feature
   is bundled into this commit. The later operator uses a separately reviewed
   offline lane; it is not a prerequisite of A or B.

Local repository-maintained lanes on the selected Engine are primary proof.

Changes to a test-only recorder do not automatically require requalifying
unchanged production deployments. Choose checks from the actual effect
