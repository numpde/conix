Execution choice
----------------
Retain one core writer across consecutive successful advances, close it at the checked tip, then poll with no advisory lock held. A source/SQL failure terminates rather than reopening automatically.

Shared T0-7 components
----------------------
- Installed `python -I -m conix run`: follows new blocks without external
  drivers and exits on source, branch, SQL or ambiguous COMMIT failures.
- Existing `conix.worker advance` is retained for one-block diagnostics.
- Manual `history inspect [--ancestor N]` reads retained identities even
  after a reorganization. `history repair --ancestor N` invokes the same
  RPC-checked Writer.repair_to() and journal; no automatic ancestor search.
- The named deployment interface initializes nonsecret settings once,
  prepares the pinned image/private input snapshot offline, and performs
  owner-only database initialization separately. `deployment/up` then creates
  a stopped container, checks its actual confinement and ownership, and
  starts it. `deployment/status`, `deployment/logs`, and `deployment/down`
  are repeat operations requiring only the saved deployment name. No
  automatic container restart.
- The generic selected-log scanner, writer publication, reader, API and
  source identity are shared unchanged from T0-6; no alternate publisher.

Evidence and limits
-------------------
The T0-6 core evidence is documented in note 004 §8.8. Added tests cover
orchestration behavior, named deployment selection, explicit recovery
delegation, runtime ownership admission, a real installed CLI process,
and a PostgreSQL/Anvil tip-following scenario. These tests
are source-level candidate gates until they are executed and recorded
against a selected rootless Engine and the real dapp32 acceptance fixture.
No production deployment or full T0-7 qualification is claimed here.

Compare all three on executable behavior, writer-lock lifetime, number of
sessions per catch-up block, additional code surface, process/repair
failure behavior, and actual selected-Engine qualification. Do not
conflate a green fake-worker orchestration test with journal correctness.
