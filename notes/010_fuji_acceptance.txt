Read-only Fuji PayToPlay acceptance
==================================

Selected scope: original Tier-0 application, all 17 ABI events and original
Reader calls for the November-8 PayToPlay deployment. No chain writes,
financial interpretation, sibling source changes or new recovery algorithm.

The committed fuji-acceptance deployment is the sole historical source
definition and ABI snapshot. Public source provenance and independent
creation-receipt observations live in tests/fixtures/evm/fuji_pay_to_play.json.
The ABI is pinned to dapp32 0c33dceb4697fe5b7b5ba0d14d4bb0d61b6b3696.
Creation block 60737751 contains OwnershipTransferred and ChannelCreated.
No real VoucherCollected has been identified; live coverage must not claim it.

A separate fixture campaign owns disposable PostgreSQL and a fixed-upstream,
read-method-only HTTPS gateway. Indexer/Reader use only two internal bridges;
only the gateway receives egress. No host ports or signing inputs are granted.
The ordinary named Make lifecycle boots and retires both application phases.

Historical replay uses a labelled bounded RPC head at the creation block,
forwarding genuine source headers, logs and state. This is a test projection,
not evidence that Fuji itself stopped there. Recent following uses the genuine
head and records lag instead of claiming an artificial tip is current.

The recent phase creates fuji-tip-acceptance through normal config/init from
the historical definition, changing only its explicit observed start and
selecting the fixture's separate conix_rpc_test database. The generated
configuration is a test-owned immutable snapshot, not another editable
authority. It is removed only after confirmed resource retirement; failure
keeps recovery evidence. History is never skipped within an initialized DB.

Use public named configuration rendering, existing process ownership, input
staging, Reader preparation and resource admission. Do not subclass the Anvil
campaign or add a general campaign framework. Gateway and probe are test-
runner-only helpers; never part of the installed runtime.

The online Fuji lane remains separate from ordinary offline CI. Required
proof includes fixed upstream/method admission and actual write denial, exact
creation logs against independently pinned receipt fields, original Reader
asset/viewPosition calls, recent genuine blocks, fresh process restart,
unchanged durable prefix, explicit budgets and owned cleanup.

Implement and qualify on tier-0, then merge upward into tier-1 and qualify
its source tree. This tests the default CLI on either branch. Selecting a
retained Tier-1 composition remains a separate operator-interface decision;
this campaign must not claim that default deployment activates D2. Main stays
stable until a separate promotion.
