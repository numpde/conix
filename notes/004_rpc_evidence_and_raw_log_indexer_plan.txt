Conix — pristine generic Tier 0: design, evidence, and execution plan
=====================================================================

Date: 2026-11-09
Status: T0-6 GENERIC CORE QUALIFIED (2026-11-11); T0-7 STANDALONE
        APPLICATION PLANNED, NOT IMPLEMENTED OR QUALIFIED.
Section 8.8 records the qualified core, its evidence and its limitations.
Section 11 is the governing standalone application plan. Sections 1–8
retain the initial generic-core requirements and implementation decisions.
This note owns product scope, correctness, public API,
source identity, journal and release gates. Note 005 is the SINGLE authority
for historical RPC acquisition methods, admitted evidence and Tier-2 method
substitution. Note 000 governs concrete delegation by later tiers.
Notes 001 (PayToPlay-only) and 003 (design workshop) are historical.

Decision: START FRESH. There is no production Conix database, schema,
checkpoint, log history, API contract or deployed worker to migrate or keep
compatible. Existing PayToPlay-specific Conix code is disposable. Delete
or replace it as needed. No dual write, read adapter, historical-schema
upgrade, replay-to-old-format, compatibility shim or cutover ceremony.
Set up a new schema against a fresh database and index from the explicit
origin. Only reusable scientific facts, tests and design lessons are worth
lifting. In particular, do not keep a bad interface merely because the
current experimental implementation or a test happens to use it.

Question being solved
---------------------

Can one small, correct, operator-run Python package, with one ABI-driven
scanner and one PostgreSQL journal, index selected events from ordinary
EVM contracts and let a consumer retrieve exact event history and
block-pinned read-only contract values?

Yes: make that the whole of Tier 0. It must work for PayToPlay, ERC-20
and ERC-721 WITHOUT changing Conix's source. It must be independently
useful with no Tier 1 recovery service, Tier 2 accelerator, SQL/JSON
expression language, application-specific adapter or external API.

A checkpoint is a statement about a complete SELECTED block prefix
UNDER AN EXPLICITLY TRUSTED RPC SOURCE. It is not a claim that the RPC
is honest, that blocks are permanently finalized, or that data before
the chosen origin is known. An empty indexed result is not proof that
nothing happened before the origin. No feature may silently strengthen
these claims beyond the available evidence.

Why the scope is this size
--------------------------

Several fixed contracts/events on ONE chain, with ONE start block and
ONE shared checkpoint: IN Tier 0. A single-contract configuration
would establish type-genericity, but adding a cross-contract checkpoint
later would change the core's completeness, error and publication
semantics. It is straightforward to establish now: obtain all selected
events for block N, then commit one complete block. If any acquisition
fails, commit none. This deliberate coupling is simpler than independent
per-contract cursors. Separate start heights, independent checkpoints,
dynamic contract discovery and multiple chains are OUT.

Position-filtered history: IN Tier 0. PayToPlay's actual consumer wants
collections for a (customer, channelId), not every collection by every
customer. Filtered pagination is a core query contract with its own
coverage/cursor semantics, not a speed trick. Do not implement a global
PayToPlay page API first and retrofit a second query method later.

Raw log storage: IN Tier 0. Store exact topics and data; do not store
generic ABI-decoded PostgreSQL numeric/JSONB fields. The consumer can
obtain typed values by ABI decoding when reading. This removes several
lossy type transformations without eliminating the obligation to
validate every supported ABI shape, including before publication.

Read-only eth_call: IN Tier 0, explicitly separable from event ingestion.
Calls use the full ABI and a checkpoint hash. A provider that cannot
execute an old state call may still deliver valid historical event logs.
Do not require latest-head code presence before indexing past events.

Manual repair and restart after uncertain COMMIT: IN Tier 0. A program
that cannot recover safely under an operator's explicit command is not
a complete Tier 0. Automated recovery, backoff and session restarts are
Tier 1; prefetch, caching, batching and throughput tuning are Tier 2
unless essential resource limits demand a smaller change to base code.

ABI support: a declared and TESTED subset, not a vague "all Solidity"
claim. Reject unsupported types or layouts at configuration admission.
Large numbers, nested values and indexed dynamic hashes must not
silently coerce, truncate, or be presented as original preimages.

1. Concrete product boundary
----------------------------

Operator inputs (illustrative TOML only; no second configuration DSL):

    version = 1

    [chain]
    chain_id = 31337
    genesis_hash = "0x<32 bytes>"
    rpc_url = "http://anvil:8545"
    start_block = 1

    [contracts.payment]
    address = "0x<20-byte address>"
    abi_file = "abi/PayToPlay.json"
    events = ["VoucherCollected(address,uint256,address,uint256,uint256,bytes32)"]

    [contracts.token]
    address = "0x<20-byte address>"
    abi_file = "abi/ERC20.json"
    events = ["Transfer(address,address,uint256)"]

Database roles, connection inputs, resource limits and work deadlines
are explicit. The program checks the chain ID/genesis; it binds source
identity to chain/genesis, origin, selected addresses, complete selected
event ABI declarations (including indexed flags) and catalog version.
An alias is a configuration identifier, not another deployed contract.
Reject duplicate addresses, duplicate selected events and incompatible
same-contract event layouts. Freeze a local immutable, bounded snapshot
of ABI bytes at preparation; no runtime download or ambient path access.
An event-selection change starts a fresh source; the first version does
NOT expand an existing indexed prefix in place. Changing view-only
function declarations should not require reindexing unchanged events.

Do not make ABI types from TOML, generate SQL tables per event, add
arbitrary transforms, consumer assertions, grouped-view definitions or
an untyped plug-in handler. ABI files are the single type vocabulary.

No signing/transaction submission, contract deployment, financial
accounting, live discovery, HTTP/GraphQL, WebSockets, subscriptions,
event-to-event joins or derived balances in the base package.

2. ABI contract and failure boundaries
--------------------------------------

At preparation, compile one coherent descriptor per selected event and
readable function. Resolve canonical signatures AND complete indexed
layouts against their CONTRACT. ERC-20 and ERC-721 Transfer share topic0
but differ in indexed flags; both must work with the SAME generic code.
Within one contract, same topic0 with incompatible layouts is ambiguous
and must be rejected, not guessed. Anonymous events are unsupported in
the first release.

Explicit minimum admitted types:
  - uintM/intM (8 <= M <= 256, multiples of 8), address, bool, bytes1..32;
  - dynamic bytes, UTF-8 string, fixed/dynamic arrays and tuples in
    nonindexed data and view/pure arguments/returns, within explicit
    maximum nesting, element count and encoded size;
  - indexed dynamic/array/tuple fields as their on-chain 32-byte HASH,
    not as reconstructed Python values.

Preserve positional argument identity for unnamed ABI arguments; expose
names only when unique and unambiguous. Indexed equality filters are
initially available only for uniquely named STATIC SCALARS listed above.
If a filter names a missing, duplicate, nonindexed, hashed or unsupported
field, reject it explicitly. Avoid a name-normalization layer that
collapses distinct ABI fields or PostgreSQL's identifier truncation.
Unrecognized or malformed ABI JSON, overloaded function ambiguity,
encoding padding errors, wrong tuple shape, overflowing integers,
booleans supplied as integers, or invalid UTF-8 result data must fail.

The type matrix describes SUPPORTED and REJECTED combinations for each
operation: admission, log decoding, indexed-filter encoding, call-input
encoding and call-output decoding. All accepted combinations must have
independent boundary vectors and actual-wire tests. One descriptor
governs every relevant boundary. Do not create redundant ad hoc
PayToPlay codecs.

ABI-valid logs containing economically odd amounts, unexpected payees
or unrecognized invoice hashes are nevertheless valid EVENT facts.
Conix must retain them. Financial interpretation belongs to PayToPlay.

3. Storage and one complete-block publisher
------------------------------------------

Initialize NEW owner-controlled PostgreSQL tables; do not attempt to
read or transform the current experimental collections schema.

    source_progress:
        exact source/catalog identity; history origin; nullable last
        complete block; generation and revision; blocked reason.
        The observed RPC head is not durable publication progress.

    blocks:
        contiguous indexed block number, hash, parent hash, timestamp;
        include blocks containing NO selected events.

    events:
        block number/hash; transaction hash and transaction index;
        block-global log index; emitting address; topic0, nullable
        topic1/topic2/topic3; original data bytea.

Each topic is validated to exactly 32 bytes; missing topics are NULL,
not zero words. Original data is exact bytea (including empty bytes).
Use an occurrence identity based on chain block + log index and verify
transaction hash/index consistency; do not identify logs by transaction
hash alone. Source-specific log_index sequences may be sparse because
other events were not selected. Forbid duplicate/overlapping acquisition
selectors in configuration; conflicting or duplicate returned occurrences
must fail the block rather than be silently ignored.

For next block N, the ONE concrete advance operation:

  1. Acquire an exclusive writer and read the checked durable basis.
     Verify configured chain and retained checkpoint compatibility.
  2. Obtain the identified next block header and continuity evidence.
     Acquire a bounded raw evidence set covering EVERY selected contract/
     event. The default uses blockHash eth_getLogs; Note 005 defines other
     admitted forms and their qualification. Do not acquire only events
     matching a consumer's later customer or channel predicates.
  3. Through ONE concrete Tier-0 validator, prove coverage of every
     selected blockHash log query and validate original envelopes:
     block identity, address, topics/data, transaction/log indices,
     order, uniqueness and structurally correct ABI values. Enforce
     response/work limits. See Note 005 for future alternative evidence.
  4. Recheck candidate canonicality and preceding checkpoint
     compatibility BEFORE publication. A changed branch, missing
     evidence or failed acquisition prevents the ENTIRE block from
     publishing, regardless of other successful/empty responses.
  5. In ONE short SQL transaction compare expected generation/revision,
     write every event and the block, update the complete checkpoint and
     commit. No RPC inside the transaction.
  6. On an unanswered COMMIT or connection loss: retire the writer,
     stop, and require fresh durable-state inspection on the next
     explicit run. Do not replay the assumed-failed mutation.

Blocks are committed individually; the worker can exit on failure. At
the tip, still check whether a same-height retained block was replaced.
An intentional manual repair selects an identified retained ancestor,
revalidates against durable basis, deletes the orphaned suffix and
changes generation/revision atomically; old cursors fail even under an
A -> B -> A history. Explicit full rebuild uses the NEW schema and
configured origin and is destructive only when intentionally invoked.
Never auto-migrate or drop arbitrary existing data at startup.

Owner-only schema bootstrap (no superuser), separate restricted runtime
writer and read-only consumer identities, explicit Docker engine context,
confined filesystems/networks, no credentials in reports, bounded
operations and cancellation are part of Tier 0. No retry framework or
high-tier hooks are prerequisites.

4. One generic reader and a precise meaning of "complete"
----------------------------------------------------------

Proposed Python operations:

    checkpoint = await reader.checkpoint()

    page = await reader.events(
        checkpoint=checkpoint,
        contract="payment",
        event="VoucherCollected(address,uint256,address,uint256,uint256,bytes32)",
        where={"customer": customer, "channelId": channel_id},
        cursor=None,
        limit=100,
    )

    position = await reader.call(
        checkpoint=checkpoint,
        contract="payment",
        function="viewPosition(address,uint256,address)",
        arguments=(customer, channel_id, actor),
    )

    evidence = await reader.evidence(
        checkpoint=checkpoint,
        block_numbers=(100, 105),
        include_finalized=True,
    )

The journal only publishes a checkpoint AFTER every source was processed
through its block. A reader cannot claim prior coverage, unfinished
blocks, or independent RPC completeness. A zero-match query is a valid,
complete EMPTY RESULT only for a selected event/filter inside that
known complete prefix. The returned page identifies start of coverage,
selected checkpoint, source/catalog identity and invalidatable generation.

Typed 'where' equality encodes ABI indexed scalar values to the exact
topic bytes and uses byte equality in SQL. Do not turn uint256 into
PostgreSQL NUMERIC or a lossy JSON number. Decode matching logs by the
event descriptor on return. Return exact Python integers, byte arrays,
tuple/array shapes and source metadata, retaining the distinction
between indexed hash values and actual dynamic preimages.

Pages are ordered by (block_number, transaction_index, log_index).
Use bounded keyset continuation, not OFFSET over matching rows or the
old PayToPlay-global sequence count. Cursors bind source/catalog,
history generation, event selection, exact filters, checkpoint and
last returned occurrence. Tier 0 permits continuation ONLY against the
same checkpoint; a newer checkpoint requires a new query. Ordinary
appends should not invalidate older complete checkpoints. Any repair
or source change must reject stale cursors. An actual empty page must
not advance a cursor past undisclosed matching rows.

Read-only view/pure calls take the ABI input and function signature,
pin eth_call to the checkpoint's blockHash with requireCanonical=true,
decode and validate its return, then recheck generation/branch.
Missing historical state, missing code at the SELECTED block, a
reverted call or unsupported EIP-1898 must fail explicitly; never
silently fall back to latest. Availability of historical views does
not determine validity of previously ingested log history.

Block evidence returns identified ancestry and, if requested and
available, source-reported finalized ancestry. Unknown state differs
from a proven fork. A validated checkpoint is not financial finality.

Basic PostgreSQL indexes supporting the actual Tier-0 query (including
topic2-only and topic3-only filters) and bounded queries are mandatory.
More elaborate indexes or denormalizations require measured benefit
and should not change reader semantics.

5. Executable sequence and release gates — ALL Tier 0
------------------------------------------------------

Each stage produces real executable behavior and negative tests.
These are incremental commits within ONE Tier-0 release, not
self-standing product tiers. No obligation to retain old Conix files,
classes, schema, names, protocol methods or test harness layout.

T0-0. Specify the installed contract and test fixtures BEFORE writing
the scanner. Choose the exact config schema, source identity, supported
ABI matrix, public reader types/cursor/failure categories, fixed
resource bounds and SQL ownership model. Establish independent
ERC-20/ERC-721 event vectors, a compound ABI fixture, actual PayToPlay
event ABI, and a concrete end-to-end Anvil/PostgreSQL harness.

T0-1. ABI compiler and codec, entirely independent of PostgreSQL.
Reject ambiguous/unsupported layouts. Golden vectors from a different
encoder, property generation with persistent failure seeds, malformed
topics, canonical padding, overflow, signed edges, arrays/tuples and
same-signature ERC-20/721. Exit: one descriptor can encode indexed
filters and decode exact events and view inputs/outputs.

T0-2. Fresh schema, configuration admission, one writer, raw journal.
Use dedicated owner/runtime/read roles. Exercise actual PostgreSQL
bytea round trips, uniqueness, sparse occurrence indices, two writers,
concurrent readers, empty blocks, config drift, source identity,
SQL failure before/after COMMIT and real process termination.
Exit: no partial publication or unknown-commit double write.

T0-3. One concrete scanner with blockHash eth_getLogs and one
selected-log evidence admission path. Multi-contract/event blocks
are mandatory. Hostile RPC exercises wrong chain, forks, ignored or
missing selectors, duplicates, out-of-order events, timeouts, oversized
or truncated results, empty blocks and contradictory identities.
Exact generic ABI validation runs before commit. Exit: only verified
complete selected evidence under the trusted RPC model advances one
block. Receipt validation is NOT a requirement until receipt acquisition
becomes a justified, reviewed shared-core feature (Note 005).

T0-4. One reader for events(), call(), checkpoint(), evidence().
Test topic equality for ALL admitted indexed scalars, filtered-empty
versus unknown history, sparse pagination, wrong filter/cursor, old
checkpoint after append, invalidation after repair, EIP-1898 and
unavailable historical state. Real Postgres, real Anvil and independent
wire fixtures, not only mocked decoder outputs.
Exit: same ABI and history give exact results after restart.

T0-5. Demonstrate generality and real consumption with ONE installed
package. Deploy and emit actual ERC-20 and ERC-721 transfers; their
identical signatures/different layouts decode without source edits.
Deploy actual supported PayToPlay; produce a signed voucher, collect,
index, obtain customer/channel-filtered history, obtain block-pinned
position state, and execute the real payment cycle. PayToPlay owns
its accounting and monetary guards and must prove a complete history
from its accepted-obligation origin, not use Conix to interpret invoices.
No fallback to the old PayToPlay observer; no compatibility shim.
Exercise restart and manual reorg/reconciliation. If that integration
exposes a generic gap, fix ONE shared Tier-0 API rather than adding
special-case behavior in Conix.

T0-6. Close release qualification: one supported-type matrix, real
Anvil/PostgreSQL end-to-end suite, adverse RPC and SQL fault matrix,
cancellation/cleanup, bounded execution, owner confinement and
correct packaging of every test/fixture. Measure baseline per-block
catch-up, retained history size and filtered query plans. These
measurements select basic indexes and reveal later Tier-2 work;
Tier 0 needs no promised throughput beyond explicit finite bounds.
Record the exact concrete core operations for future delegation
proofs, without prebuilding extension infrastructure.

T0-6 qualified the selected ABI, scanner, journal, reader and one-shot
worker, NOT a continuously running standalone indexer. The missing
application lifecycle is T0-7 (section 11), without invalidating or
inflating the T0-6 evidence in section 8.8.

Exit standard: remove ALL future-tier code and the installed Tier-0
package remains correct and operator-usable. One wrong ABI value,
dropped configured log, false complete page, stale usable cursor,
partial block, unauthorized DB mutation, hidden latest fallback,
or PayToPlay economic safeguard lost during consumer integration
blocks this release. Existing PayToPlay-specific unit-test successes
do not qualify the new program; tests may be reused as independent
facts, but not as proof of API/implementation compatibility.

6. Later tiers — explicit non-goals of this implementation
----------------------------------------------------------

Tier 1: unattended resilience around the entire T0-7 standalone
application. On classified recoverable failures it may back off, retire
and reopen the application, or select a canonical repair ancestor and
invoke the SAME checked Tier-0 repair. Any narrow read retry must still
delegate to the concrete core and preserve its evidence and deadlines.
Tier 1 does not own or duplicate normal block scheduling, catch-up or
tip following. No parallel publisher or repair SQL. An unattended
recovery scenario and selected live-RPC qualification are Tier-1
operations tests, not reasons to make Tier 0 depend on a paid provider.

Tier 2: measured PHYSICAL acquisition and bounded I/O assistance only.
Note 005 owns permitted RPC strategy changes, prospective receipt
evidence, range-query caveats and qualification. Optimizations that
reuse the selected-log evidence form delegate to the SAME Tier-0
validator and publisher. New evidence/completeness formats require a
reviewed shared-core enhancement when actually needed, never a second
scanner or a silently substituted publication. No speculative extension framework.

Outside these tiers: new EVM business semantics, arbitrary expression
filters, unindexed-field global indexes, derived balances, generated
application-specific tables, GraphQL/HTTP, message brokers, signing,
transaction submission, distributed active-active writer election,
cross-chain joins, indefinite histories without provenance, and
provider-quorum consensus.

8. T0-0 public contract — frozen choices for first generic implementation

This section records the T0-0 decisions implemented by the qualified
generic Tier-0 core. It remains normative for source identity, admission and

8.1. Configuration and admission
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

ONE TOML document (schema version 1) with exactly:
    version
    [chain] chain_id, genesis_hash, start_block, rpc_url
    [contracts.<alias>] address, abi_file, events
    [database] dsn_file, runtime_role
    [limits] rpc_timeout_seconds, operation_timeout_seconds,
             max_response_bytes, max_connections, max_page_size,
             max_evidence_blocks, max_logs_per_block, max_abi_bytes,
             max_abi_nesting, max_abi_elements

The following is a COMPLETE form, aside from real hashes/addresses/paths:

    version = 1

    [chain]
    chain_id = 31337
    genesis_hash = "0x<exactly 64 lowercase hex digits>"
    start_block = 1
    rpc_url = "http://anvil:8545"

    [contracts.payment]
    address = "0x<40 hex digits>"
    abi_file = "abi/PayToPlay.json"
    events = ["VoucherCollected(address,uint256,address,uint256,uint256,bytes32)"]

    [contracts.erc20]
    address = "0x<another 40 hex digits>"
    abi_file = "abi/ERC20.json"
    events = ["Transfer(address,address,uint256)"]

    [database]
    dsn_file = "/run/conix/connection.dsn"
    runtime_role = "conix_runtime"

    [limits]
    rpc_timeout_seconds = 5
    operation_timeout_seconds = 30
    max_response_bytes = 1048576
    max_connections = 4
    max_page_size = 100
    max_evidence_blocks = 64
    max_logs_per_block = 10000
    max_abi_bytes = 1048576
    max_abi_nesting = 8
    max_abi_elements = 4096

The TOML file has a 64 KiB maximum, must decode as UTF-8 and must have
unique, exactly admitted keys. Contract aliases match [a-z][a-z0-9_]{0,63}.
Require 1..32 contracts, 1..256 distinct selected events over the complete
catalog, one start_block and one chain. Require chain_id and start_block to
be ordinary Python integers in [0, 2^63-1], never bool. Addresses are 20-byte
hex; accept lowercase or a valid EIP-55 mixed-case checksum, reject invalid
mixed case, and normalize internally to bytes. All returned public addresses
use EIP-55 checksum display. Genesis is 32 bytes, lowercase hex in TOML.
No default or ambient chain, database, RPC, credential, limit or Docker Engine.

The rpc_url is an absolute http(s) URL with a host and no userinfo or fragment.
Do not log it or embed it in source identity. Operator policy separately
authorizes the network and private credential handling. In particular, a
proxy that excludes eth_call cannot be silently bypassed for historical reads.

ABI input is one JSON array per contract, read only from an explicit local
regular file. Relative abi_file resolves relative to the TOML file directory;
absolute paths are admitted under the explicitly staged input authority.
Reject symlink files and ancestor traversal, network fetches, duplicate JSON
members, malformed UTF-8, unmatched event signatures, duplicate declarations
and ABI size overflows. Read and freeze each ABI as an immutable snapshot
BEFORE opening RPC or database sessions; later disk edits cannot change a
live session's descriptors. File formatting, unrelated ABI events, mutating
functions and ABI entry ordering are not event-history changes. Selected
events and all readable view/pure functions are validated at preparation.
No selection/configuration-defined ABI type system exists.

A single catalog selects each deployed ADDRESS exactly once, regardless of
alias. Reject overlapping selectors and ambiguous same-contract topic0
layouts. ERC-20 and ERC-721 may share topic0 on DIFFERENT addresses, with
different indexed argument layouts.

8.2. Source identity, catalog changes and handles
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Construct source_id as SHA-256 of this canonical logical event-selection
document, not of raw ABI files, operator aliases, RPC URLs or TOML bytes:

    schema = "conix.source.v1"
    chain_id = canonical base-10 integer string
    genesis_hash = lowercase 0x-prefixed 32-byte hex
    start_block = canonical base-10 integer string
    events = sorted list, ordered by address bytes then event signature

Each event record includes 20-byte normalized emitting address, canonical
event signature, anonymous=false and the FULL positional input layout:
canonical ABI type tree (including tuple/array component shapes), original
input name (including empty or duplicate names) and indexed boolean.
The serialized document uses UTF-8 JSON, lexicographically sorted object
keys, no insignificant whitespace and ASCII escapes for non-ASCII names.
Byte values use lowercase hex, numbers in the document are decimal strings.
There is no unstable hash of Python dictionaries, file mtimes or JSON source
order. Every component of this encoding has literal input/output tests.

source_id is the database's history authority. Selected ABI event name/type,
indexed flags, contract address, origin or chain identity changes REQUIRE
fresh history; no in-place extension of a previously complete prefix.
Changing ABI JSON whitespace, unselected event declarations, RPC endpoint,
credentials, local alias, runtime limits or available view/pure functions
does NOT require a rebuild. Reader aliases and view/pure descriptors live in
a separately identified immutable read catalog; their changes may reject an
old query handle, but may not change retained event-history identity.

A running worker checks the durable source_id at startup and before any
publication. A source mismatch is an error, not a reason to initialize a
second owner schema or silently drop old data.

8.3. Public Python surface and exact value rules
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Keep one installed Python distribution. These module/function names form the
first generic contract, not implementation-stub extension points:

    from conix.catalog import prepare_catalog
    from conix.abi import compile_event, decode_event, encode_indexed_filter
    from conix.core import open_writer
    from conix.reader import open_reader

    catalog = prepare_catalog(config_path)       # sync, offline, no RPC/DB

    async with open_writer(
        catalog=catalog,
        database_dsn=runtime_dsn,
        rpc_url=selected_rpc_url,
    ) as writer:
        result = await writer.advance_one()       # at most one complete block

    async with open_reader(
        catalog=catalog,
        database_dsn=reader_dsn,
        rpc_url=selected_rpc_url,
    ) as reader:
        checkpoint = await reader.checkpoint()    # Checkpoint | None
        page = await reader.events(
            checkpoint=checkpoint,
            contract="payment",
            event="VoucherCollected(address,uint256,address,uint256,uint256,bytes32)",
            where={"customer": customer, "channelId": channel_id},
            cursor=None,
            limit=100,
        )
        value = await reader.call(
            checkpoint=checkpoint,
            contract="payment",
            function="viewPosition(address,uint256,address)",
            arguments=(customer, channel_id, actor),
        )
        facts = await reader.evidence(
            checkpoint=checkpoint, block_numbers=(100, 105),
            include_finalized=True,
        )

The caller explicitly owns both context managers; neither may select a
different RPC endpoint, database, Docker context, or implicit credentials.
The owner-only initialize(owner_dsn, catalog) is a separate one-shot
administrative API; writer and reader cannot create or alter schema.
The checked manual repair_to(ancestor identity) is exclusively a writer
operation, fenced by source generation/revision, and never automated in Tier 0.
A timed-out run must retire its owned sessions; a blocked state stops instead
of quietly retrying.

Public immutable values, in meaning rather than incidental field ordering:

  Block(number: int, hash: bytes32, parent_hash: bytes32, timestamp: int)
  Checkpoint(source_id: bytes32, generation: UUID, history_start: int,
             block: Block, revision: int)
  Event(contract: alias, event: canonical signature, address: EIP55 string,
        block: Block, transaction_hash: bytes32, transaction_index: int,
        log_index: int, topics: tuple[bytes32, ...], data: bytes,
        values: tuple[typed ABI values, ...])
  IndexedHash(topic: bytes32)    # NOT a decoded dynamic original value
  EventPage(checkpoint: Checkpoint, history_start: int,
            events: tuple[Event, ...], next_cursor: Cursor | None,
            complete: bool)
  CanonicalEvidence(checkpoint: Checkpoint, blocks: tuple[Block, ...],
                    finalized: Block | None, finalized_status: known/unknown)

Return exact Python int (not bool), EIP-55 address str, bool, immutable bytes,
UTF-8 str and recursively nested tuples for tuples/arrays. Unnamed arguments
retain their original POSITION. Provide exact names only when unique.
For indexed dynamic/array/tuple values, return IndexedHash wrapping the exact
32-byte topic. Do not compare it with, or masquerade it as, an ABI preimage.
Callable view/pure results are tuples even for one return; a tuple-valued
return is nested inside that outer tuple. No additional PayToPlay Position
model, balance computation or consumer validation lives here.

compile_event takes a selected ABI event declaration (without network or
database), returns a complete descriptor and rejects ambiguity/cap breaches.
decode_event(descriptor, topics, data) yields a positional tuple.
encode_indexed_filter(descriptor, field_name, Python value) yields exactly
one 32-byte topic. It is restricted to uniquely named indexed static scalar
fields. No adapter can silently accept an array/hash/name ambiguity.

8.4. ABI admitted/rejected combinations
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The machine-readable type matrix is tests/fixtures/abi/support_matrix.json.
Qualify every accepted operation; do not infer support from a library having
a decoder for a shape. Included families:

  uint8..uint256 and int8..int256, multiples of 8;
  address, bool, bytes1..bytes32;
  dynamic bytes, string, fixed/dynamic arrays and tuples recursively.

Only indexed uint/int, address, bool and bytesN have typed SQL topic equality.
Indexed bytes/string/arrays/tuples are accepted as hashed ABI topics, never as
recoverable values and never as scalar equality-filter candidates. All admitted
families support nonindexed events and view/pure inputs/outputs within bounds.
Reject function and fixed/ufixed ABI value families for first release, as
well as malformed arrays, anonymous events and invalid UTF-8.

Compile canonical argument shapes and verify every entry's indexing layout.
Reject too many indexed arguments (>3 for nonanonymous events), wrong topic
count, invalid 32-byte padding, uint/int range/sign extension violations,
invalid bool words, bad dynamic offset graphs, overlapping/trailing tails,
noncanonical ABI encoding, integer supplied as bool, wrong tuple dimensions
or output shape, and unrecognized/ambiguous overload selection.
No float coercion, automatic integer truncation, string-to-bytes conversion,
normalization of ABI argument names or data-dependent SQL column names.

8.5. Complete-block publisher and SQL ownership
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Store only source_progress, blocks and events in NEW owner-controlled tables.
Every block from origin through checkpoint is represented in blocks even if
it contains no selected events. The events table retains exact emitting
address, all original topic words (missing topic slots NULL), original data
BYTEA, block/transaction hashes, indices and validated log occurrence.
Uniqueness is by block identity + block-global log_index, NOT transaction hash
and NOT an invented per-contract event sequence. Selected log indices may
have gaps when unrelated events occur in the same block.

One advance_one() acquires an exclusive writer and checked durable basis;
identifies one block and obtains a complete admitted raw evidence set for
EVERY configured selection. It executes ONE Tier-0 evidence/ABI validator,
checks IDs, order, duplicates, continuity and canonicality, and commits
events + block + checkpoint atomically with a generation/revision CAS.
The initial physical method is blockHash eth_getLogs; Note 005 owns
the admission boundary and any justified future evidence format. No RPC runs inside
the SQL transaction. Any failed/incomplete acquisition publishes NOTHING,
including when other selectors are empty. At the tip, check the retained
hash against the live canonical branch. Unknown COMMIT retires the writer
and requires fresh durable-state inspection on the next explicit run.

Dedicated PostgreSQL identities, provisioned externally:
  conix_owner:  non-superuser schema owner, only explicit install DDL;
  conix_runtime:  restricted DML to own journal, no CREATE/TRUNCATE/DDL;
  conix_reader:  SELECT-only on the journal, no DML/DDL.

Grant no ledger or other application-schema access. Runtime and reader DSNs
are distinct private inputs; owner credential never enters normal worker or
reader. Initial schema is created on an empty explicitly selected database,
not silently migrated from prototype collections. A reader uses REPEATABLE
READ or equivalent consistent snapshot, validates source/generation/blocked
status before and after the page, and never allows a repair/rebuild to rebind
old handles. Any RPC read is pinned to the selected checkpoint block hash
and rechecks durable generation/branch afterward.

8.6. Filtering, pages, calls and evidence
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The where mapping is equality-only on uniquely named indexed static scalar
arguments, validated and topic-encoded BEFORE SQL. Compare bytes in one of
topic1/topic2/topic3, including topic2-only and topic3-only predicates.
Filters use a canonical ordered list of argument ordinal + exact topic bytes,
independent of user dict insertion order. No OFFSET, SQL expression language,
Python post-filter that can miss pages, or unindexed-field scan fallback.

Order pages by (block_number, transaction_index, log_index). Cursors use an
opaque, bounded, fully checked representation binding source_id, generation,
exact event identity/alias, canonical filters, selected checkpoint number/hash,
and last returned occurrence. A continuation may use only the SAME selected
checkpoint. An append preserves an older checkpoint's usable complete prefix;
a repair/rebuild invalidates all old-generation cursors, including A->B->A.
complete=True means no further matching selected events up through THIS
checkpoint; next_cursor is None then. A zero-match complete page proves only
no matching selected events within [history_start, checkpoint].

Historical calls invoke EIP-1898 eth_call with
{"blockHash": checkpoint.block.hash, "requireCanonical": true}.
They MUST NOT fall back to latest or silently change to block-number pinning.
Reject absent historical state, missing code at that checkpoint, reverted
calls, noncanonical output data and unsupported block-hash selectors. These
are availability errors independent of the completeness of stored logs.
Evidence includes identified block ancestry plus optional provider-reported
finalized ancestry; unavailable finality is UNKNOWN, not a proven fork and
not independently established consensus.

8.7. Hard limits and rejection policy
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

All configured limit values are required; each also has a fixed code ceiling:

  rpc_timeout_seconds       0 < value <= 60
  operation_timeout_seconds 0 < value <= 300
  max_response_bytes        1 .. 4194304
  max_connections           1 .. 32
  max_page_size             1 .. 500
  max_evidence_blocks       1 .. 64
  max_logs_per_block        1 .. 10000
  max_abi_bytes             1 .. 1048576  (per ABI file or encoded payload)
  max_abi_nesting           1 .. 8
  max_abi_elements          1 .. 4096     (per decoded array)

The fixed aggregate raw-event cap for one candidate block is 8 MiB; at most
8 MiB total ABI-file bytes are admitted in one prepared catalog. The scanner
does not stream unbounded RPC results or allocate a decoded array based solely
on an untrusted ABI length. T0-1's strict codec further caps the SUM of
elements across all nested arrays in a single ABI value at four times the
configured per-array max_elements; the same cap applies to caller encoding
and wire decoding. Tuple/array nesting is checked before library grammar
expansion, including cyclic malformed in-memory declarations. One block transaction and every SQL operation
has an explicit bounded deadline. Exhaustion is an UNAVAILABLE operation,
never evidence of an empty selected history.

Failure categories are public, stable, typed and scrubbed of source payloads:

  ConfigurationError        invalid/inconsistent local catalog
  UnsupportedABI            unsupported/ambiguous ABI at admission
  InvalidCallerValue        wrong Python value for an admitted ABI descriptor
  RpcUnavailable            timeout/transport/upstream availability
  RpcProtocolError          malformed/contradictory provider evidence
  BranchConflict            retained history versus observed canonical branch
  HistoryUnavailable        missing, blocked or invalidated complete prefix
  CursorInvalid             mismatched/retired cursor or checkpoint
  HistoricalCallUnavailable unavailable/reverted/unsupported pinned eth_call
  ResourceExceeded          admissible input exceeds an explicit budget
  WriterBusy                concurrent writer lock denied
  CommitOutcomeUnknown      PostgreSQL COMMIT confirmation lost; stop safely
  StorageUnavailable        durable SQL operation could not be proven complete

Do not expose upstream response text, credentials or raw call inputs in public
exceptions. Preserve original error cause/phase privately; cleanup outcomes
are reported separately and the primary failure remains LAST. A simple
ordinary RPC failure must not be silently retried under a stronger claim.

9. Existing libraries — deliberate reuse decision (2026-11-10)
---------------------------------------------------------------

This decision narrows the implementation of T0-1; the public contract and
T0-1 acceptance requirements above are unchanged. The goal is one small
Conix boundary over tested external primitives, NOT another ABI package.

Already locked in pyproject.toml (as inspected on 2026-11-10):
  eth-abi 6.0.0, eth-utils 6.0.0, eth-typing 6.0.0,
  eth-hash 0.8.0, HTTPX 0.28.1 and psycopg 3.3.6.

Use these directly:
  eth_abi.grammar.parse / normalize for Solidity ABI grammar and canonical
  type trees; eth_utils.abi.collapse_if_tuple for JSON tuple components;
  eth_utils.abi.abi_to_signature, event_abi_to_log_topic and
  function_abi_to_4byte_selector for signatures/selectors;
  eth_abi.encode / decode for ordinary ABI words, arrays, tuples, call
  inputs and returns; eth_utils for EIP-55 address representation and Keccak;
  HTTPX AsyncClient for bounded explicit JSON-RPC transport, with trust_env
  disabled; psycopg AsyncConnection for the actual SQL transaction and
  BYTEA transfer. Do not implement replacements for these primitives.

Conix STILL owns a small descriptor/compiler:
  - reject unsupported ABI families BEFORE alias/type normalization;
    normalizing a type string cannot silently make an unsupported original
    type admitted; reject ambiguous same-topic layouts, duplicate names where
    public lookup would be ambiguous, bad indexed flags and unsupported
    anonymous events;
  - compile selected events and view/pure functions once from staged,
    immutable, bounded ABI bytes, keyed by contract address and full layout;
  - map indexed STATIC scalar values into one 32-byte topic using
    eth_abi.encode after exact Python type/range validation;
  - map indexed dynamic/array/tuple values to IndexedHash, preserving
    the topic bytes without pretending the preimage was decoded;
  - split topics and nonindexed payload by the declared ABI, decode
    with eth_abi.decode(..., strict=True), and require exact
    eth_abi.encode(types, decoded) == original_bytes. Decode/encode
    equivalence rejects noncanonical or trailing representations, but is
    not a substitute for upstream RPC checks, input budgets or the
    independent Solidity-wire test vectors;
  - check all resource budgets BEFORE handing any untrusted nested
    offsets/lengths/response bodies to a general decoder. Catch and classify
    library exceptions; never publish a partially decoded event;
  - reject bool as integer, float/string coercions, invalid EIP-55 mixed
    case, noncanonical UTF-8, wrong array/tuple shapes or ABI width overflows
    before encoding supplied filter/call values.

DO NOT introduce web3.py as a production dependency merely to get
ContractEvent.get_logs, process_receipt, filter builders, or eth_call.
web3.py 8.0.0 (2026-08-31) supplies those useful public APIs, but its
high-level event handling includes permissive error options; documented
process_receipt(errors=WARN) discards erroneous logs. ContractEvent.get_logs
can also perform client-side filtering of NONindexed arguments. Conix must
inspect all selected raw logs and refuse a block if any are malformed, so
high-level decoded-event results are not authoritative acquisition evidence.
A test-only, independently maintained web3.py decoder may provide additional
differential checks, with STRICT error handling and literal wire oracles.

eth-event 1.4.10 (2026-06-21) is a narrower maintained event-decoding library,
but it duplicates the installed eth-abi/eth-utils primitives and does not
replace Conix's ABI-layout, completeness, publication or query contracts.
Likewise, psycopg_pool is a supported optional pool, not a Tier-0 necessity;
a pool's background reconnection must not introduce silent recovery when a
publication outcome is unknown.

rindexer (Rust), Ponder (TypeScript) and other external indexers ALREADY
implement ABI-driven event fetching, PostgreSQL integration and reorg handling.
They are viable alternatives to Conix as an entire product if Python-native
in-process reading, one selected-history checkpoint, raw-log provenance and
Conix's explicit failure/repair semantics are not requirements. They are not
drop-in Python codec or journal dependencies. Do not copy their callbacks,
derived tables, GraphQL API, acceleration or implicit recovery into Tier 0.

What remains ORIGINAL in Conix is the trust-boundary protocol, not ABI math:
  - verified selected-set raw RPC evidence and an explicit acquisition contract
    (physical strategies and alternate evidence forms: Note 005);
  - one shared complete-block publication, including empty blocks;
  - short fenced SQL transactions and stop-on-unknown-COMMIT;
  - checked manual suffix repair and invalidatable generation handles;
  - history-scoped, typed, sparse paginated SQL topic filtering;
  - hash-pinned read-only calls, explicit unsupported historical state;
  - separate owner/writer/read privileges and bounded contained operations.

T0-1 exit gate therefore becomes: prove the small wrapper around the existing
libraries admits EXACTLY the declared type matrix, rejects malformed wire,
maintains full indexed-layout identity and agrees with independent literals
and actual Anvil/Solidity emission. No bespoke scalar or compound ABI decoder
may be introduced without a documented, test-backed reason that a maintained
library cannot satisfy an accepted case. Do not add web3.py, eth-event or an ORM
to the runtime lock by default.

11.1. Required operational contract
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

An ordinary Tier-0 process must load the existing staged catalog and
restricted runtime credential, establish the selected source and exclusive
writer, ingest every available complete selected block in order, and wait
at the chain tip. It must notice later blocks without an external driver
and continue until explicitly stopped or an error makes continuation unsafe.

The implemented public invocation is:

    python -I -m conix run

This entrypoint delegates to the existing core. The diagnostic remains:

    python -I -m conix.worker advance

The diagnostic remains a single bounded advance and need not be rebuilt
around the new CLI. The application's installed Python runner should have
one ordinary run() operation, with a thin CLI for staging, safe diagnostics
and exit status. There is no separate work-cycle API, task scheduler,
driver registry, callback framework or IPC command server.

Normal execution, conceptually:

    load_runtime_inputs()                     # once at process startup
    until stop requested:
        with open_writer(...):                # core verifies source and basis
            until stop requested:
                progress = writer.advance_one()
                if progress is None: break     # checked chain tip
        if not stopping: await tip_poll_or_stop()

An actual implementation must handle async contexts and process signals
correctly; this is an execution contract, not copy-ready Python. Each
advance calls the installed core, retaining its exact selected-log
validation and one-transaction-per-block journal publication. Do not
repeat ABI/RPC/source validation in the application loop. Existing core
operation deadlines remain authoritative; add a distinct outer bound
only if a real uncovered wait requires it, with cancellation/COMMIT
semantics proved first.

11.2. Execution design choice
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

A — Fresh writer for each block:
    The application may repeatedly call the installed one-shot advance.
    This is a small reference design and a useful comparison, but each
    block reacquires SQL/RPC sessions, source identity and writer lock.

B — One writer while catching up (SELECTED):
    Open one writer; call advance_one() repeatedly as long as it advances;
    release the writer immediately on a checked at-tip result; wait;
    reopen it and recheck when polling. The writer retains the exclusive
    journal authority only while doing useful work. Each block still has
    its own SQL transaction, resource limit and failure boundary. Add a
    session-duration budget only in response to measured operational need.

C — Persistent command-controlled worker:
    Without autonomous looping this is not the required application.
    Adding external control alongside autonomous operation would create
    a second execution mode, IPC protocol and lifecycle. No concrete
    need justifies that architecture in the Tier-0 baseline. Do not
    develop or merge it as the normal indexer.

Use B. At the tip, release database writer ownership before waiting;
poll with a simple, bounded stop-aware interval, not a busy loop. The
next poll must traverse the same core advance path so a forked retained
tip cannot be mistaken for an uneventful chain. No new container is
created per block and no speculative multi-block transaction is allowed.

11.3. Failure, stop and restart
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Ordinary failures propagate to a nonzero process exit with bounded,
nonsecret phase/cause diagnostics. Do not automatically retry RPC,
reopen a failed writer, switch provider, choose a repair anchor or
replay an uncertain COMMIT. Explicit restart is safe only because a new
core writer checks journal progress and source identity before further
work; the prior process must never manufacture a success receipt.

SIGTERM requests termination. While idle, stop promptly; during an
advance, let the current bounded operation finish when feasible, close
the writer and exit. A signal handler does not run SQL. Cancellation
or forced kill during publication does not authorize success, and the
existing atomic journal/durable restart rules remain in force. Choose
a container stop grace consistent with the in-flight operation budget
or explicitly qualify forced termination when grace expires; do not
claim every SIGTERM is graceful. SIGKILL cannot be intercepted.

The runner has no independent resilience policy. Tier 1 may later
supervise it, but Tier 0 is itself a functioning indexer on healthy
inputs and deliberately stops on failed inputs.

11.6. Tier boundaries and excluded machinery
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

Tier 0 RUNS the complete ordinary indexer and offers explicit manual
repair. Tier 1 SUPERVISES that same application on recoverable failures,
with optional bounded recovery decisions; it must not implement another
normal indexing loop. Revise the existing main-tier-1 supervisor only
after standalone Tier 0 passes independent acceptance. Tier 2 assists
physical raw-evidence acquisition underneath the SAME authoritative
advance; Note 005 owns its possible methods and evidence restrictions.

Do not add speculative transport/provider interfaces for Tier 2 in
T0-7. Do not add duplicate catalog validators, routine internal type
checks, synthetic result envelopes, lifecycle hooks, alternate scanners,
redundant exception wrappers or generalized error taxonomies. Essential
checks remain in their actual trust owners: prepare_catalog(),
open_writer(), RPC/Writer.advance_one(), Journal and Writer.repair_to(),
plus host admission and pre-retirement ownership checks at their
distinct authority points. Keep exactly the protections that avert
concrete incorrect outcomes; no extra validation for its own sake.
